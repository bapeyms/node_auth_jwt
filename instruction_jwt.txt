JWT-АВТЕНТИФІКАЦІЯ: ВИКОНАНІ ЗМІНИ ТА ІНСТРУКЦІЯ
====================================================

Що додано
---------
1. Додано залежність @nestjs/jwt та оновлено package-lock.json.
2. Створено модуль src/auth з реєстрацією, входом і глобальним JWT-захистом API.
3. Публічні маршрути:
   POST /auth/register — створює активного користувача через UserService і повертає JWT.
   POST /auth/login — перевіряє email та пароль і повертає JWT.
   POST /user — наявний маршрут створення користувача; залишений відкритим для сумісності.
   GET / — наявний кореневий маршрут; залишений відкритим.
4. Інші маршрути потребують заголовок:
   Authorization: Bearer <access_token>
   Це стосується маршрутів користувачів, категорій та ролей.
5. Для входу перевіряються пароль і стан блокування; повідомлення про невдалий
   вхід не розрізняє неправильний email, пароль або заблокований обліковий запис.
6. Відповідь на реєстрацію/вхід містить access_token і token_type. Хеш пароля не
   повертається і більше не виводиться в консоль.
7. Додано unit-тести сервісу авторизації.

Налаштування
------------
1. Скопіюйте .env.example у .env або додайте змінні до свого локального .env.
2. Встановіть JWT_SECRET довжиною щонайменше 32 символи. Приклад генерації
   криптографічно випадкового секрету в PowerShell:
   node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
   Не використовуйте наведений вище приклад як готовий секрет і не додавайте
   справжнє значення секрету до системи контролю версій.
3. JWT_EXPIRES_IN — термін дії токена у секундах; значення за замовчуванням 3600.
   Значення JWT_SECRET з відсутньою або коротшою за 32 символи довжиною, як і
   невалідне значення JWT_EXPIRES_IN, зупинить запуск застосунку з помилкою.
4. Налаштуйте змінні підключення до бази даних. Для реєстрації має існувати роль
   користувача з id=2; за потреби виконайте npm run seed:roles та перевірте
   відповідність ідентифікатора ролі даним у базі.
5. Запуск у режимі розробки: npm run start:dev

Приклади запитів
----------------
Реєстрація:
POST /auth/register
Content-Type: application/json

{
  "email": "user@example.com",
  "password": "secret-password",
  "fullname": "Test User"
}

Вхід:
POST /auth/login
Content-Type: application/json

{
  "email": "user@example.com",
  "password": "secret-password"
}

Звернення до захищеного ресурсу:
GET /user
Authorization: Bearer <access_token>


Для повного запуску потрібні налаштовані JWT_SECRET і доступна база даних.
